# v0.4 검증: 바른 로컬 · 사전 분석 입력 · 연어/N-gram

검증 환경: Linux x86_64 / Python 3.12.14 / PyQt6 6.12.1. `bareun-baropy==3.4.1`의 PyPI wheel을 배포 SHA-256과 대조해 소스를 확인하고 설치했습니다. 기존 Kiwi·바른 API·UTagger 어댑터와 버전 1 프로젝트 형식은 유지합니다.

## 실행

```bash
python -m pip install -r requirements.txt
python -m pip install -e '.[morphology,bareun,baropy,utagger,test]'
QT_QPA_PLATFORM=offscreen python -m pytest -q
```

전체 회귀 테스트와 `git diff --check`를 수행했습니다. 아래의 실제 SDK/프로세스 사용과 대역 사용 범위를 구분합니다. GUI는 실제 Qt 이벤트 루프를 사용하는 offscreen 테스트이며, Windows/macOS 네이티브 창의 수동 검증은 아닙니다.

전체 회귀 결과: **49 passed in 15.77s**. 바른 로컬 관련 6개 테스트도 별도로 통과했습니다. UI 테스트는 선택 SDK의 설치 상태에 따른 버튼 활성화를 확인합니다. offscreen/Fontconfig 캐시 안내는 있었지만 한글 렌더링과 기능 검증은 완료했습니다.

## 바른 로컬

- 공식 `baropy.Bareun(api_key=..., background=False, cache_dir=..., threads=...)`, `analyze`, `dicts.put`, `release` API를 확인했습니다. API 방식과 로컬 방식을 UI/저장 설정에서 구분합니다.
- SDK 소스에서 `var/api-keys.db.pb`, 라이선스, 로그가 생성됨을 확인했습니다. 프로젝트/분석 DB에 키를 넣지 않고 키 등록·로그를 임시 세션 폴더에 격리합니다. 모델만 별도 캐시에 보존합니다. 강제 종료로 남은 임시 폴더는 정상 정리를 보장할 수 없음을 README에 기록했습니다.
- **실제 baropy SDK + 시험용 루프백 서버 프로세스**로 토큰 기반 자식 연결, 키 등록, 요청/응답 파싱, release를 실행했습니다. 이 시험 서버는 한국어 모델이 아니며 외부 라이선스 서버를 호출하지 않습니다.
- **실제 별도 Python 프로세스 + SDK 역할 대역**으로 키를 argv/env에 싣지 않는 IPC, 모델 재사용, 등록 파일·로그 삭제, 동시 캐시 잠금, 대기 중 취소와 자식 종료를 검증했습니다.
- host 함수 테스트에서 실제 SDK 결과 타입을 사용하고 SDK 모델 호출만 대체해 사용자 고유명사, 발화 경계 유지, 의미 어깨번호 옵션과 release를 확인했습니다.
- 실제 Qt 창에서 API/로컬 옵션 구분, 직접 입력한 키의 비밀번호 표시, 키 없이 실행 비활성화, 옵션 복원 시 키 제외, 창 닫기 시 키 제거를 확인했습니다. 모델 캐시를 원본 말뭉치 내부에 두면 쓰기 전에 거부합니다.
- **미검증:** 실제 유효 키로 네이티브 서버의 모델 다운로드·라이선스 인증·형태소 정확도. 실제 키를 제공받지 않아 수행하지 않았으며 이를 성공한 것으로 보고하지 않습니다.

## 사전 분석 파일

- 사용자 요청에 따라 TXT `형태소/품사`를 기본값으로 제공합니다. 한 줄 한 발화, 마지막 `/` 구분, 공백/탭 토큰 분리, `//SP`, `+/SW`, `배__05/NNG`, CP949/BOM을 확인했습니다. 선택적으로 `형태소/품사+형태소/품사`도 분리합니다.
- JSON 경로·객체 키/쌍 목록, 빈 배열 발화, 실행식을 허용하지 않는 경로 파서, TSV 빈 행 경계, Excel 동일 ID 연속 행 묶음을 검증했습니다.
- 잘못된 입력 파일은 그 파일의 부분 행을 롤백하고 다음 파일을 처리합니다. 원본 바이트 불변, SQLite 결과의 복사/검증, 가져오기 취소 후 임시 DB 삭제를 확인했습니다.
- 가져온 형태소와 품사를 자동 보정하거나 분석기로 다시 보내지 않습니다. 텍스트 미리보기는 형태소에서 재구성한 것임을 표시합니다.

## 통계

- 손으로 계산할 수 있는 `가 나 가` 예제에서 MI=1, t-score=1/√2, logDice=14, 공기 빈도·슬롯 주변합을 검산했습니다. 중심어 지정 전후의 배경 분모가 같은지도 확인했습니다.
- N-gram의 n/품사 포함, 품사 필터, 같은 차수 전체 N-gram 분모, 발화 경계 설정, 파일 경계 유지, 전체 수 0일 때 설명을 확인했습니다.
- 연어의 좌우 범위, 전체 쌍/중심어, 최소 빈도, 필터 후 거리 미압축, 전 후보 기반 빈도·점수 정렬을 확인했습니다.
- 6,005개 서로 다른 형태소로 6,004종 bigram과 12,008종 방향 연어 후보를 만들고, 5,000개 배치 경계를 넘어 디스크 집계·전체 후보 정렬·상위 조회를 확인했습니다.
- 실제 Qt에서 **3,000줄 TXT → 가져오기 → N-gram → 연어 → 설정/결과 저장 → 프로젝트 다시 읽기 → 저장 통계 열기**를 실행했습니다. 분석기 호출을 금지한 대역을 걸어 실제 재분석이 없음을 확인했고, Qt 타이머가 계속 실행됐습니다.
- 작업자/SQL progress handler에서 취소를 확인하고 미완료 DB를 제거합니다. 기존 완료 결과는 유지합니다. 정렬은 전체 후보의 DB 조회이며 표 머리글 정렬은 미리보기 범위임을 문서화했습니다.

## 별도 3,000개 TXT GUI 실험

하위 폴더에 실제 합성 TXT 파일 3,000개를 생성했습니다. 997번째 간격의 4개 파일은 품사 누락으로 의도적으로 실패시켰습니다. 원본 폴더를 연결하지 않은 새 프로젝트에서 실제 가져오기/통계 창을 열고 수행했습니다.
