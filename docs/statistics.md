# 연어 · N-gram의 입력과 집계 기준

앱의 형태소 분석 결과와 사전 분석 파일에서 불러온 결과는 동일한 SQLite 발화 테이블을 사용합니다. 통계 작업은 분석기를 호출하지 않습니다. 토큰은 `(형태소, 품사)`이며 입력 순서, 원본 파일, 발화 ID를 보존합니다. 표의 설정과 생산자(`producer`) 메타데이터는 저장 당시 값입니다.

## 경계와 품사

- 기본값은 발화 경계를 넘지 않습니다. **발화 경계 넘기**를 켜면 같은 파일 내 발화를 연결하고, 파일이 바뀌면 항상 초기화합니다. 파일 간 가상 연결은 만들지 않습니다.
- 품사 필터는 쉼표로 구분한 접두어의 합집합입니다. `NN*` 또는 `NN`은 `NNG`, `NNP` 등을 포함하고, `VV`는 `VV`, `VV-R` 등을 포함합니다. 빈 칸/`*`는 전체입니다. POS 체계를 자동 변환하지 않습니다.
- **N-gram**은 선택 품사만 남긴 뒤 연속 묶음을 만듭니다. 따라서 `밥/NNG 을/JKO 먹/VV`에서 `NN,VV`를 선택하고 n=2이면 `밥 먹`이 생성됩니다.
- **연어**는 제외 품사를 건너뛰되 탐색 거리를 압축하지 않습니다. 위 입력의 좌/우 1 범위에서 `밥`과 `먹`은 공기하지 않고, 범위 2에서는 공기합니다. 통계 후보와 중심/결합 토큰 모두 품사 필터를 만족해야 합니다.

## 문장부호·형태소 제외 (v0.6.4 보완)

- 통계 설정의 **문장부호·가운뎃점 제외**는 형태소 전체가 Unicode 일반 범주 `P`(문장부호) 또는 `·ㆍᆞ⋅∙・･` 문자로 구성되면 제외합니다. 단독 아래아와 수학 연산자로 분류된 일부 점도 포함되며, 아래아 자체를 연구할 때는 자동 제외를 끄고 추가 제외 목록을 사용하세요. `"`, `?`, `…`, `“`, `”`, `?!` 등을 포함합니다. 품사 태그가 다르더라도 같은 문자 기준을 적용합니다.
- 단어와 부호가 섞인 `C++`, 수학기호 `+`, 이모지는 자동 제외하지 않습니다. **추가 제외 형태소**에 한 줄에 하나씩 입력해 제외할 수 있습니다. 형태소 전체 정확 일치이며 품사와 관계없이 제외합니다. `것`을 적어도 `그것`은 제외되지 않습니다. 쉼표는 구분자가 아니므로 쉼표 자체도 한 줄에 입력할 수 있습니다.
- N-gram은 품사·제외 조건을 적용한 뒤 남은 토큰을 이어 묶습니다. `“ 동일하 ㄴ 것 ” ?`의 문장부호를 제외하면 3-gram `동일하 ㄴ 것`이 만들어집니다. 형태소 사이의 표시 공백은 유지합니다.
- 연어는 제외된 토큰을 후보·토큰 빈도·공기 슬롯에서 빼되 **탐색 거리는 원래 위치를 유지**합니다. `밥 " 먹`에서 `"`를 제외해도 두 단어의 거리는 2이므로 범위 1에서는 공기하지 않습니다. 문장부호 제외는 문장 경계를 새로 만드는 기능은 아니며 발화·파일 경계 설정을 따릅니다.
- 핵심도는 대상·참조 양쪽에 같은 제외 조건을 적용하고, 제외 후 같은 n의 전체 N-gram 수를 각 분모로 사용합니다. 제외 설정은 집계 캐시 키에 포함됩니다.
- 기본값은 문장부호 제외 꺼짐, 추가 목록 없음으로 기존 설정의 동작을 유지합니다. 체크한 뒤 분석 종류의 계산 버튼을 다시 누르세요. 이미 저장된 결과는 그대로이며 새 결과와 내보내기 설정에 `exclude_punctuation`, `excluded_forms`를 기록합니다. 제외 후 0개면 조건을 확인할 수 있도록 이유를 표시합니다. 새 기준으로 제외할 때는 `punctuation_filter_version=2`를 설정과 캐시 키에 넣어 이전 기준의 집계를 재사용하지 않습니다. 결과 하단의 필터 상태는 편집 중인 체크가 아닌 저장된 설정을 나타냅니다. 원문과 형태소 DB는 수정하지 않습니다.

## N-gram

n은 1~10입니다. 같은 발화의 필터 후 토큰 수를 L이라고 하면 생성되는 n-gram은 `max(0, L-n+1)`개입니다. 경계 넘기를 켜면 같은 파일의 연결된 토큰열에 이 식을 적용합니다. 중첩 발생을 모두 셉니다.

형태소만 옵션에서는 서로 다른 품사라도 형태소가 같으면 같은 항목으로 합칩니다. 품사 포함 옵션에서는 `(형태소, 품사)`의 순서열로 구분합니다.

- 빈도 `c(g)`: 해당 n-gram의 발생 횟수.
- 전체 `T_n`: 현재 품사·경계·n 설정에서 생성된 **같은 차수**의 모든 n-gram 수 (`Σ_g c(g)`).
- 백만 n-gram당 상대 빈도: `c(g) / T_n × 1,000,000`.

`T_n=0`이면 빈 표와 함께 발화 길이·n·품사·경계 조건을 확인하라는 이유를 표시합니다. 상위 10행이 기본 미리보기이며, 전체 후보는 DB에 저장됩니다. 이 분모를 그대로 이용해 아래의 대상/참조 2×2 핵심도를 계산합니다.

## 연어: 방향이 있는 탐색 슬롯

좌 L·우 R 범위의 각 중심 **위치 i**에서 결합 **위치 j**를 방문합니다. `i-L ≤ j ≤ i+R`, `i≠j`인 실제 위치 중 품사 필터와 경계 조건을 만족하는 슬롯만 셉니다. 두 형태소가 같더라도 위치가 다르면 후보가 될 수 있습니다.

후보는 방향이 있는 `(중심 형태소/품사, 결합 형태소/품사)` 쌍입니다. 양방향 범위에서 `(가, 나)`와 `(나, 가)`는 별도 항목입니다. 한 중심 주변에 같은 결합어가 여러 번 있으면 각 위치를 셉니다. 따라서 단순 토큰 빈도와 공기 슬롯 주변합을 구분합니다.

- `f_x`, `f_y`: 전체 입력에서 품사 필터를 만족하는 각 형태소/품사의 **토큰 빈도**. 표의 ‘중심/결합 토큰 빈도’입니다.
- `O_xy`: 관측된 `(x,y)` **슬롯 빈도**. 표의 ‘공기 빈도’입니다.
- `M_x = Σ_y O_xy`: 중심 슬롯 주변합. 표의 ‘중심 슬롯 주변합’입니다.
- `M_y = Σ_x O_xy`: 결합 슬롯 주변합. 표의 ‘결합 슬롯 주변합’입니다.
- `N = Σ_xy O_xy`: 전체 유효 슬롯 수. 저장 메타데이터의 `population`입니다.
- 기대 빈도 `E_xy = M_x M_y / N`.

중심어를 지정하더라도 **전체 중심 위치의 배경 슬롯과 주변합을 먼저 계산한 뒤** 표시 후보를 제한합니다. 지정 중심어 안에서만 배경을 만들면 MI가 퇴화하므로 그렇게 계산하지 않습니다. 최소 공기 빈도도 배경 분모를 바꾸지 않고 표시 후보에만 적용합니다. 중심어 입력은 형태소에 대한 정확 일치이며, 서로 다른 품사는 별도 행으로 표시합니다.

지표:

| 지표 | 식 |
| --- | --- |
| MI | `log₂(O_xy / E_xy) = log₂(O_xy N / (M_x M_y))` |
| t-score | `(O_xy − E_xy) / √O_xy` |
| logDice | `14 + log₂(2 O_xy / (M_x + M_y))` |

관측 공기 빈도 1 이상인 후보만 계산합니다. 여기서는 여러 좌우 위치를 같은 확률 표본으로 비교하기 위해 **슬롯 주변합**을 사용합니다. 단순 토큰 빈도를 주변합으로 대입하는 다른 도구와 점수가 다를 수 있습니다. `f_x`, `f_y`는 연구자가 빈도를 함께 확인하도록 별도로 보여주며, 이 식의 분모에 넣지 않습니다.

검산 예: 발화 `가/NNG 나/NNG 가/NNG`, 좌우 1이면 `O_가나=2`, `M_가=2`, `M_나=2`, `N=4`, `f_가=2`, `f_나=1`입니다. 기대 빈도 1, MI 1, t-score 약 0.70710678, logDice 14입니다. 중심어 ‘가’를 지정해도 같은 점수여야 하며 자동 테스트에서 확인합니다.

## 저장·조회·자원 제한

통계 설정, 원래 형태소 생산자/옵션, 발화 수, 선택 토큰 수, `T_n` 또는 `N`, 전체 후보 수, 전체 결과를 `.results/statistics-<SHA256>.sqlite`에 저장합니다. 원본 토큰 DB와 입력 파일은 수정하지 않습니다. 다시 열 때는 저장된 설정을 하단에 표시하며 위의 편집 중인 새 설정과 구분합니다.

후보 Counter는 최대 약 5,000개에서 SQLite로 배치 집계합니다. 슬라이딩 창은 최대 좌+우+1 또는 n개만 유지합니다. 한 번에 읽는 발화의 토큰 배열 자체는 메모리에 들어갑니다. Excel ID 열을 비우거나 JSON에서 매우 큰 배열을 한 발화로 선택한 경우 그 배열 크기가 메모리에 영향을 줍니다.

전체 결과 정렬·상위 조회는 작업자에서 SQLite로 수행합니다. UI에는 10·100·1,000행만 표시합니다. 표 머리글은 미리보기 안에서만 정렬하며, 전체 후보 정렬은 ‘정렬/표시 적용’을 사용합니다. SQL 집계/정렬은 progress handler로 취소를 확인합니다. 취소한 미완료 DB는 제거하고 기존 완료 결과는 보존합니다. API/형태소 재분석과 통계 계산은 별도 작업입니다.

## 참조 기반 N-gram 핵심도

두 말뭉치에서 **동일한 n·품사 필터·품사 포함·발화/파일 경계**를 적용합니다. 표본의 전체 수는 원래 토큰 수가 아니라 같은 차수의 생성된 N-gram 수입니다. 두 후보 집합의 합집합을 비교하고 한쪽 미출현은 0으로 둡니다.

| | 해당 N-gram | 나머지 N-gram | 합계 |
| --- | ---: | ---: | ---: |
| 대상 | a | b = T_target − a | T_target |
| 참조 | c | d = T_reference − c | T_reference |

총합 `S = a+b+c+d`. 기대빈도 `E_ij = (행 합계 × 열 합계) / S`입니다.

- 로그 우도비: `G² = 2 Σ O_ij ln(O_ij/E_ij)` (자연로그). `O_ij=0`의 항은 0으로 둡니다.
- 피어슨 카이제곱: `χ² = Σ (O_ij−E_ij)²/E_ij`. Yates 보정은 하지 않습니다.
- 열 주변합이 0이면 그 열의 관측값도 모두 0이므로 해당 0/0 항은 제외합니다. 모든 발생이 같은 단일 항목인 퇴화 표의 통계량은 0입니다.
- 부동소수점 오차로 생기는 극소 음수는 0으로 제한합니다.
- 방향은 `a/T_target`과 `c/T_reference`를 정수 교차곱으로 비교하여 대상/참조/동일로 표시합니다. 통계량 자체는 음수가 아닌 값입니다.
- 상대 빈도는 각 말뭉치의 전체 N-gram 수를 분모로 한 백만 단위입니다.
- 4개 기대빈도 중 최솟값과 5 미만 존재 여부를 표시합니다. 낮은 기대빈도 전용 조회는 전체 후보 중에서 필터링한 뒤 정렬/상위 제한을 적용하므로 일반 상위 미리보기 밖의 항목도 확인할 수 있습니다. 구조적인 0 기대빈도도 표시합니다. 이 표시는 근사 통계량 해석을 위한 정보이며 p값이나 자동 유의성 판정이 아닙니다.
- 한쪽 `T_n=0`이면 나눗셈/비교를 실행하지 않고 어느 쪽에서 왜 생성되지 않았는지 설명하는 빈 결과를 저장합니다.

### 비교 가능한 분석 결과

Kiwi는 저장된 버전·CoNg 모델 식별자·받침/복합 분리/자모 옵션·사용자 사전 내용을 비교합니다. 바른 API는 버전·전처리·보정 옵션·사전 이름 순서, baropy는 버전·의미 어깨번호·고유명사 사전, UTagger는 버전·실제 모델/사전 파일 지문을 확인합니다. 텍스트 추출 경로는 달라도 됩니다. 모델 캐시 위치와 CPU 스레드 수는 내용 동일성에서 제외합니다.

서버 모델 또는 외부 사전 분석 자료의 실제 생산 과정을 검증할 수 없을 때는 동일 분석/전처리/품사/사전 사용을 사용자가 확인해야 합니다. 이 확인을 결과에 기록하고, 결과 쌍을 바꾸면 UI 확인을 해제합니다. 서로 다른 분석기나 알려진 옵션 불일치를 사용자 확인으로 무시하지 않습니다.

`.results/.ngram-counts` 캐시 키에는 **형태소 DB 전체 바이트의 SHA-256**과 공통 N-gram 설정이 포함됩니다. 입력 변경이나 n/품사/경계 변경은 다른 캐시를 만듭니다. 캐시의 설정·완료 여부·집계 합계와 분모를 확인하며, 손상된 캐시는 다시 만듭니다. 지표만 바꾸면 같은 집계를 사용합니다. 원본 파일을 다시 읽거나 형태소 분석기를 실행하지 않습니다.

### 내보내기

형태소·연어·N-gram·핵심도 모두 전체 결과를 스트리밍으로 내보냅니다. CSV는 UTF-8 BOM과 설정 JSON을, XLSX는 전체 결과와 설정 시트를 제공합니다. 핵심도 설정에는 `target_ngrams`, `reference_ngrams`, 지표·n·POS·경계·생산자·동일성 확인이 포함됩니다. UI 미리보기의 행 수 제한은 내보내기에 적용하지 않습니다.
